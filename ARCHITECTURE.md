# Architecture

ACGS-Lite is a **constitutional governance membrane** that sits immediately before a
side-effectful agent action and returns a verifiable ALLOW / DENY / TRANSFORM decision with
a receipt. It is a library, not an agent framework — it does not own model calls, prompting,
planning, memory, or orchestration. See [`GOAL.md`](GOAL.md) for the product boundary and
core invariant; this file is the system-design map. For the deep lifecycle write-up see
[`docs/architecture.md`](docs/architecture.md).

## Core invariant

> No valid constitutional authorization, no side effect.

The runtime fails **closed** whenever authorization, constitution version, policy state,
receipt integrity, or audit evidence cannot be verified.

## Runtime flow

```text
LLM reasoning
   │  proposed side-effectful action + active constitution state
   ▼
GovernanceEngine.validate()            src/acgs_lite/engine/
   │  matcher → rule evaluation        src/acgs_lite/constitution/, matcher.py
   ▼
ALLOW / DENY / TRANSFORM  ──► decision receipt (bound to method, scope, subjects,
   │                          policy version, execution boundary)
   ▼
MACI role check (Proposer ≠ Validator ≠ Executor)   src/acgs_lite/maci.py
   │
   ▼
Governed execution  ──► tamper-evident audit entry   src/acgs_lite/audit.py
```

Infrastructure-integrity failures (missing/stale/tampered receipt, unknown constitution, MACI
violation, unverifiable audit) fail closed and raise. Policy violations are reported through the
validation result in non-strict flows and may raise `ConstitutionalViolationError` in strict flows.

## Modules

| Module | Responsibility |
| --- | --- |
| `src/acgs_lite/constitution/` | Rules, lifecycle, bundle store, HTTP lifecycle router |
| `src/acgs_lite/engine/` | Validation engine + bundle binding |
| `src/acgs_lite/maci.py` | MACI separation-of-powers enforcement |
| `src/acgs_lite/audit.py` | Tamper-evident, replay-verifiable audit trail |
| `src/acgs_lite/governed.py` | Drop-in governed wrappers around agent execution |
| `src/acgs_lite/agents/` | Agent **discovery**: capability profiles, registry, governed selector |
| `src/acgs_lite/compliance/` | Regulatory mapping and assessments |
| `src/acgs_lite/integrations/` | Optional external adapters (lazy-imported) |
| `src/acgs_lite/server.py` | FastAPI surface (`create_governance_app`) |
| `src/acgs_lite/commands/` | CLI wiring (`acgs ...`) |
| `rust/` | Optional Rust acceleration with a Python fallback |

## Two-layer agent discovery

Agent routing has two layers that share **one** schema so they cannot drift:

1. **Discovery** — [`agent-index.json`](agent-index.json) (root) is loaded by
   `acgs_lite.agents.AgentRegistry` and ranks candidate agents for a task. The per-agent
   manifests under [`agents/`](agents/README.md) are a generated projection of it.
2. **Decision** — `GovernedAgentSelector` makes a fail-closed, receipted, MACI-respecting
   selection. See [`docs/api/agents.md`](docs/api/agents.md).

`agent-index.json` is the single source of truth; `agents/*.agent.yaml` are generated by
`make agents-sync` and guarded against drift by `make validate` and
[`scripts/agent_ready.py`](scripts/agent_ready.py).

## Design rules (load-bearing)

- Optional integrations stay lazy — never import optional SDKs at module import time.
- Keep a Python fallback whenever optional Rust/third-party acceleration exists.
- Never bypass MACI enforcement in wrappers or integrations.
- Never change `matcher.py` hot-path behavior without targeted tests.
- Constitutional hash `608508a9bd224290` is part of the validation flow.

The forbidden-pattern table and conventions live in [`AGENTS.md`](AGENTS.md); the rationale
for key choices is in [`DECISIONS.md`](DECISIONS.md).
